# 股选优前端升级记录

## 实施范围

按已批准计划升级五个工作区，桌面和手机同等验收。保持 React / TypeScript / 原生 CSS / Lucide / Tauri 技术栈、原有接口与本地存储。

阶段：基线 → 全局规范 → 选股与自选 → 观察 → 回测 → 消息与 Agent → 集成验收。

## 已锁定设计约束

- 桌面表格、手机列表；使用同一排序和格式化逻辑。
- 品牌红只用于主要动作与选中，涨跌和系统状态分别表达。
- 密度不再改变字号。默认正文 14、数据 13、辅助 12、标题 18px；偏小和偏大分别减／加 1px。
- 手机主要交互区域至少 44px，紧凑模式不缩小触控目标。
- 768px 以下为手机布局；769–1180px 紧凑侧栏与辅助抽屉；1181px 起消息可三栏；1600px 起保留现有宽屏居中。
- 不新增框架、图表库、CDN 字体或业务接口；不清空和迁移用户存储。

## 基线证据

- 改动前构建通过：入口 gzip 35.5 KiB；CSS gzip 35.90 kB；观察／回测／消息／Agent 懒加载块分别约 22.26／10.20／15.76／14.85 kB gzip。
- 改动前截图覆盖已有 harness 全部设备与工作区；旧版完整构建另存，便于同环境比较。
- 改动前对比度检查通过：24 个路由／主题／视口组合。
- 初始单元测试通过 59 文件、382 测试。完整测试命令后半段与并行开发交叠，因此不能作为完整的改动前通过记录；最终必须重新运行。
- 固定 100／500／1000 条数据渲染中位耗时：44.8／172.9／367.5ms。收藏：30.2／30.1／40.7ms。展开测量是否实际触发控件需在最终对照中核实。
- 浏览器插件未提供；使用仓库已有 Playwright 与固定数据验证。
- ADB 可用，但 `adb devices -l` 没有连接设备；Android 实机软键盘、安全区、返回键和原生全屏标记待验收。

## 验证入口

- `npm test`：完整既有测试链。
- `npm run build`：类型、生产构建、包预算。
- `node scripts/ui-upgrade-check.mjs <输出目录>`：五个工作区、主题、密度、字号和边界尺寸矩阵；检查可见内容、运行异常、溢出、重复 ID、移动触控尺寸并输出代表截图。
- 现有 `scripts/ui-screenshot.mjs`：业务交互与视觉基线；只有经检查的设计变更可更新对应基线。

临时截图、浏览器记录、性能对照位于此次 Codex 任务的 visualizations 目录，不提交生成的构建文件。
