# HK market provider readiness

**Checked on:** 2026-10-27
**Decision owner:** release engineering
**Scope:** ordinary-share HK observation and financial enrichment in this application.

This record is an engineering release gate, not a legal opinion. A reachable endpoint, an API credential, a user authorization flow, a public web page, or a parser fixture does not grant an automated-access, caching, display, redistribution, or model-processing right. No market-data, financial-data, or news provider is approved here for live refresh or public-app display; the separately scoped ECB HKD/CNY reference-rate exception below is not a market-data stack. Fixture-based parsing and read-only local-cache views remain available while the corresponding live refresh is blocked.

The full dated comparison, rights matrix, source links, and opening conditions are in the [current market-provider evaluation](market-provider-evaluation-2026-10-27.md). “Documented” in that evaluation means an official API page describes the operation or response shape; it does not mean exchange licensing, completeness, or permission for this application.

## Release rules

1. `ensure_hk_provider_ready` is the current live-request gate for HKEX, Tencent, Eastmoney HK, and HKEXnews. It must cover direct refresh commands and foreground recovery paths, not only the visible UI action. Moomoo and Longbridge are unevaluated runtime candidates; this documentation does not create an adapter or open a gate for them.
2. Capability status uses both provider readiness and data evidence. Existing cache records cannot open a closed provider gate. A cache-backed capability is at most `limited`; no usable records means `unavailable`.
3. `classification_status` defaults to `unverified` when loading older cache files. Do not convert HKEX's `Equity` category or the subcategory text into `ordinary_share` evidence.
4. A provider can be enabled only after this record includes the signed/official permission reference, authorized purpose, allowed fields, cache duration, public-app and per-user BYOK display/redistribution scope, derived-analytics and model-processing scope, rate limits, required attribution, and review date. Update the integration tests and release gate in the same change.
5. Real-network verification is a separately authorized operational check. Automated tests use fixtures and never contact these endpoints.
