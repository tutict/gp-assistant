# 安卓端股票分析 Skill 设计

本文档固化 APK 内置股票分析 Skill 的第一期边界。手机端 Agent 页面不是桌面端同步包的附属功能，而是可以独立做轻量实时个股分析的入口。

## 目标

- APK 内置股票分析 Skill prompt、输出 schema、防偏规则和轻量分析器。
- 手机端 Agent 页面输入股票代码或名称后，可以分析近期利好、利空、中性和待验证线索。
- 第一期开启无需登录、无需 Cookie 的公开信源。
- 雪球、东方财富股吧等社区源默认关闭，后续通过用户自填 Cookie 启用。
- 手机端只做短期缓存，不构建长期 RAG。

## 非目标

- 不默认连接同一局域网桌面端 Agent 服务。
- 不在 APK 中嵌入 AkShare/Python。
- 不在手机端抓取需要登录、强 Cookie 或高反爬的社区源。
- 不输出买卖建议、仓位建议、目标价或收益承诺。

## 第一批信源

`CNINFO/巨潮公告` 是公告、财报披露主源。用于识别官方披露的利好、利空、中性事项。

`通达信 F10/财务快照` 是公司资料、财务摘要、经营分析补充。它可用于财务快照和经营概况，但不能替代公告原文。

`公开新闻 URL/网页标题摘要` 是传统媒体和新闻补充。第一期支持用户手动输入 URL 或系统可访问的公开新闻源。

社区源第一期不默认启用。即使后续启用，也只能进入待验证线索。

## 输出区块

手机端 Agent 分析结果固定为 5 个区块：

1. `结论概览`：利好、利空、中性、待验证数量和总体判断。
2. `利好因素`：每条带来源和证据。
3. `利空因素`：每条带来源和证据。
4. `中性信息`：公告披露、财务摘要、普通新闻。
5. `待验证线索`：来源不足、社区讨论或未验证信息。

## 单条结论 schema

```json
{
  "label": "positive | negative | neutral | unverified",
  "title": "简短标题",
  "summary": "一句话解释",
  "source_tier": "filing | financial_snapshot | news | research | community | manual_url",
  "source_name": "巨潮资讯 / 通达信 / 第一财经 / 手动URL",
  "published_at": "2026-06-08",
  "evidence": "原文片段或摘要依据",
  "confidence": 0.0,
  "risk_note": "为什么不能过度解读"
}
```

## 可信度规则

- `filing` 可以形成最高可信结论。
- `financial_snapshot` 可以支持财务变化，但需要注明快照属性。
- `news` 可以形成支持性线索，但需要保留来源和时间。
- `research` 是观点和预测线索，不能当作官方事实。
- `manual_url` 视来源质量给中等置信度。
- `community` 只能输出 `unverified`。

没有来源证据时必须输出“未找到可靠信源”，不能编造结论。

## 防偏规则

Skill 必须遵守：

- 不输出“买入”“卖出”“满仓”“清仓”“目标价”“稳赚”“必涨”等建议。
- 只能输出“选股研究视角下的利好/利空因素”。
- 必须提示“仅供选股研究，不构成投资建议”。
- 社区/未验证消息不能写成确定事实。
- Agent 生成的判断只能作为分析缓存，不能当作事实证据。

## APK 内置边界

APK 内置以下内容：

- Skill prompt。
- 结构化输出 schema。
- 防偏规则。
- 轻量分析器。
- 短期缓存字段。
- 公开信源 adapter 的统一接口。

APK 不内置：

- Python/AkShare 运行时。
- 长期 RAG 构建器。
- 全量向量库。
- 默认社区 Cookie。

## 与上下游 RAG 包的关系

手机端有两条能力：

- `上下游 RAG 包`：桌面端构建，扫码导入，服务于单目标股票一跳上下游证据链。
- `Agent 实时个股分析`：APK 内置 Skill，面向任意个股做轻量实时利好利空分析。

两者互补。Agent 可以读取已导入的 RAG 包增强上下游分析，但不能把没有证据的结论写成事实。
