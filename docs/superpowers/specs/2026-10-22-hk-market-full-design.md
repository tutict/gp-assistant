# 港股完整研究能力设计

## 状态与目标

本设计取代 [`2026-10-19-hk-market-mvp-design.md`](2026-10-19-hk-market-mvp-design.md) 中“港股只提供行情观察”的阶段性范围。港股目标是覆盖 README 公开承诺的研究工作流：市场目录与自选、观察与指标、筛选、回测、消息与本地 RAG、情绪快照、研究 Agent，以及相应的数据维护与可用性状态。功能按数据证据成熟度分阶段交付；完整能力是产品目标，不代表所有阶段必须同时发布。

产品首期范围为香港交易所上市普通股。ETF、窝轮、债券及其他证券类别不自动继承普通股语义，后续按独立数据和策略契约扩展。A 股现有功能与数据语义必须保持兼容。

本项目提供研究和策略验证工具，不输出交易指令或收益承诺。港股功能不得将 A 股数据、A 股财务字段、交易单位、市场日历、基准指数、行业标签或评分假设伪装成港股等价数据。

## 产品结果

用户在 A 股与港股上下文之间切换时，应始终知道当前市场、证券身份、数据来源、观测时间、报告期、覆盖范围和数据质量。每个页面只读取当前市场的记录；切换市场会清除旧市场的选中证券与页面结果，同时保留多市场自选条目。

每个能力都声明其必需数据域、证券类别、适用市场、覆盖状态和校验状态。能力状态统一为：

- `available`：所需数据完整，允许按该能力的发布契约运行。
- `limited`：可以对清楚界定的证券子集、日期区间或数据范围运行；界面必须同时说明覆盖边界，结果也携带该边界。
- `unavailable`：缺少必需数据域、来源、适用市场映射或可靠性证明；不得运行，并显示缺少的证据及恢复条件。

状态由可检查的数据质量和发布契约计算，不由 UI 文案或模型判断。刷新失败保留最近有效缓存并暴露来源错误和时间；缺失值保持缺失，筛选与回测不得用零值、A 股缓存或无说明的代理值补齐。

## 市场领域契约

### 标识和测量

建立显式领域类型和序列化契约：

- `MarketId`：`cn` 或 `hk`。任何持久化市场数据、刷新请求、运行记录、证据快照和结果均带市场标识。
- `SecurityId`：由市场、规范证券代码和证券类别组成。港股代码保留前导零；证券类别必须可区分普通股和后续支持的其他类别。
- `Money` 与 `Quantity`：数值同时携带 ISO 币种或明确单位。成交量统一保存为股数；板块手数只作为证券元数据，不能参与不匹配单位的计算。
- `Observation`：记录来源 ID、来源级别、抓取时间、市场观测时间、披露/生效时间、报告期、校验状态、缺失原因和质量标记。没有对应语义的字段保持空值，不复制一个日期填充多个日期字段。
- `Coverage`：记录查询范围、成功/缺失证券数、日期边界、必需字段覆盖、排除原因和数据截点。
- `MarketCapability`：声明能力 ID、必需数据域、适用证券类别、必需字段、可运行范围、状态、缺口和重新评估条件。

前端和 Rust 之间的契约使用一个正式定义源生成或守卫，禁止两边独立手工复制同一字段表。兼容现有 A 股持久化键和 IPC 负载；迁移期间可在边界映射旧格式，内部运行统一领域类型。

### 数据域

统一的外部数据服务管理来源注册、刷新运行、重试、缓存、迁移、来源状态和可复核覆盖。适配器按能力实现以下数据域；同一域可以按市场使用不同 provider：

1. 证券主表与证券类别。
2. 当前报价和交易状态。
3. 日线及能力需要的其他频率历史行情。
4. 公司行动与复权因子。
5. 财务报表、指标及其原始报告期和首次公开日期。
6. 交易日历、上市/退市日期、停牌状态和可交易状态。
7. 市场基准、行业分类与证券成分关系。
8. 公司公告、新闻和来源链接。
9. 汇率数据，仅供明确标注的展示换算或策略用途。

Provider 声明其支持的市场、证券类别、数据域、字段、历史边界、频率、单位、来源级别和刷新约束。所有结果在进入 store 前按声明校验。未知 provider 不得通过任意 URL 成为通用 IPC 网络代理。

### 市场服务、策略与界面

市场中立的应用服务处理市场上下文、自选路由、显式刷新、缓存查询、运行状态、来源元数据和能力状态。A 股与港股的 provider 适配器负责来源协议、代码映射、字段解析、单位映射、错误分类和来源特定校验。

策略和研究分析通过显式市场策略接口运行。算法可以共享纯数学或与市场无关的组件，但其输入假设（市场范围、基准、货币、交易日、费率、复权和字段含义）必须在契约中声明。港股不支持某个 A 股专属概念时，该市场策略不得静默复用同名 A 股指标。

前端由市场能力注册表决定页面入口和操作状态，避免散布 `market === "hk"` 分支及独立占位组件。市场切换器、选股、观察、回测、消息、情绪和 Agent 使用统一的市场上下文；页面对 `limited` 和 `unavailable` 提供覆盖边界或具体缺口。

## 能力发布门槛

每项能力使用可版本化、可测试的发布契约，列出证券范围、必需数据域和字段、最大可接受陈旧度、最小日期覆盖、允许的缺失处理、算法版本和结果必须返回的覆盖信息。初始阈值由 provider 评估和 fixture 证据确定，并存入契约；不能以 UI 常量或一次在线请求替代。

筛选允许 `limited` 范围，但必须逐证券排除缺少硬性输入的数据，并报告请求证券池大小、合格数量和每种排除原因。用户显式请求完整证券池时，若契约无法满足完整覆盖则拒绝运行。所有输出绑定市场、交易日、数据截点、输入覆盖和策略版本。

回测采用 fail-closed 规则：每个调仓/成交日都必须有契约要求的点时证券状态、财务可见时间、行情、公司行动和成交规则。任何缺口都让该请求失败并列出缺失域/证券/日期；不静默删掉折次、证券或不可交易日。发布验证报告固定策略、成本、股票池、时间段、来源版本与 fixture/数据快照指纹。

新闻、RAG、情绪和 Agent 的开放条件包括可追溯来源、市场/证券归属、披露/采集时间、证据快照、质量状态和有界覆盖。不可验证的新闻可作为标记为低质量的线索，但不能单独支持确定性结论。

## 分阶段交付

### 阶段 1：统一契约、观察与财务

- 建立 `MarketId`、`SecurityId`、观测元数据、覆盖摘要与能力状态契约，并接入现有市场上下文。
- 把港股目录、报价、历史和财务接到统一外部数据服务；provider 适配器保留来源特定语义。
- 将 A/HK 观察页迁移到共享的市场驱动布局。财务候选值、汇率和官方披露元数据明确区分来源与核验级别。
- 建立港股普通股完整目录和证券类别过滤。目录接受所有符合范围的交易币种证券，除非证券/策略契约明示更窄范围。
- 阶段验收：A 股观察结果与 v0.6.2 固定契约一致；港股来源 fixture 覆盖多币种、部分缺失、陈旧和失败场景；切换市场无结果串用；Windows/Android 前端构建通过。

### 阶段 2：港股筛选与分类

- 为港股定义可复核的行业/板块分类来源、市场基准和策略注册；将通用筛选条件与市场专属因子分开。
- 对现有筛选器增加 market strategy adapter，而非把 HK 证券伪造成 CN 股票池记录。
- 实现自定义筛选、排序、合格范围摘要和当前市场自选联动；只开放数据依赖已满足的策略。
- 阶段验收：每个策略有固定多市场 fixture、指标含义/单位断言、证券隔离测试和覆盖摘要测试；缺少必要字段时显式排除或拒绝。

### 阶段 3：港股历史与回测

- 研究并接入港股历史行情、公司行动、交易日历、停复牌、上市退市及历史财务披露时点数据。
- 抽出市场无关的组合/折次编排；市场 adapter 提供选股策略、日历、复权、基准和交易成本模型。
- 为每次回测固化输入快照、策略版本、数据版本和覆盖记录；提供逐折、组合、基准和缺失证据报告。
- 阶段验收：未来数据不可见测试、缺数据 fail-closed 测试、公司行动/停牌/跨币种用例和确定性重放通过；不能生成完整点时证据前，严格港股回测状态为 unavailable。

### 阶段 4：消息、RAG、情绪与 Agent

- 将新闻/公告 provider 的归一化记录按 SecurityId 入统一外部数据 store，并实现按市场和证券检索。
- 把情绪快照 schema 改为显式市场上下文；A 股和港股各自提供证据收集器，共用快照/引用/状态机制。
- 将 Agent 工具契约从隐含 A 股语义改为显式 market-aware schema。工具、run ledger、事件流和最终结果持续校验市场与证券一致性。
- 阶段验收：跨市场同代码/近似代码隔离测试、证据 ID 引用测试、快照冻结测试、拒绝未注册市场工具测试和离线 fixture 回放通过。

### 阶段 5：旧路径清理与发布

- 清理重复港股观察组件和仅表达 MVP 范围的占位文案，统一由能力注册表生成可用性界面。
- 清理确认未引用的 provider、数据模型、辅助函数和 dead-code warnings。可选功能代码按 feature/module 正确隔离，A 股仍在使用的实现保留。
- 港股旧 JSON 到 SQLite 的迁移必须通过 schema 升级、幂等重复运行、逐域校验、损坏文件、部分迁移、磁盘写入失败、恢复重试和旧数据保全测试。发布版本先提供只读恢复路径；下一版本确认迁移成功率后才删除旧格式读取支持。
- 审查所有声明为旧的 IPC、环境变量、缓存文件与 release script 分支；有用户数据兼容或外部调用方时先经过 deprecation 周期。
- 阶段验收：版本发布脚本的前端守卫、Rust 检查/测试、桌面打包和签名 Android 构建通过；Android 与 Windows 市场切换、离线缓存、目录/财务刷新、筛选状态和迁移恢复完成真实设备/平台验收。

## 迁移与兼容性

保留现有 `app.market` 工作区键和 A 股 API 语义。内部引入市场契约时，在受控边界兼容旧 A 股 IPC payload；迁移完成后由契约测试阻止继续增长旧字段。

港股旧 `hk-market-data.json` 按安全域逐项导入统一 SQLite store，校验记录数量、证券键、源/时间/单位及 payload。仅当一个域确认导入并可从新 store 读回后，标记该域迁移完成。原 JSON 在迁移周期内保持只读恢复副本；迁移代码不得因空数据库、部分成功或 provider 暂时不可用而覆盖有效旧数据。

删除旧 JSON fallback 需要：迁移器版本稳定、重复运行幂等、所有受支持旧 schema 的 fixture 通过、写入中断恢复通过、线上诊断能够识别迁移状态，并有明确的旧副本保留/清理策略。未经用户确认的数据清理操作不得作为迁移副作用。

## 代码清理规则

- 每个 dead-code 警告追溯生产 caller、测试 caller、feature gate 和平台条件；只有确认所有目标配置均不可达且没有迁移/恢复职责时才能删除。
- 被 A 股独立使用的 CN provider、指标或 UI 不因港股改造而删除；将它们归入 A 股 adapter/strategy 边界。
- 共享通用逻辑优先复用纯函数或领域服务，不复制大段筛选/回测实现，也不为表面共用而引入带多个市场布尔分支的 god module。
- 清理每个垂直切片后运行相应 Rust/TS tests、契约测试和编译检查；完整发布前运行全量 release-check。

## 验证与可观测性

所有市场 provider 自动测试使用固定样本和 mock transport，不依赖公网。Fixture 要记录其来源/适用 schema 和更新日期；生产数据抓取不参与确定性单测。

统一日志和 UI 状态只记录脱敏请求 ID、市场、证券、数据域、provider、时间、错误类别和覆盖摘要，不记录 API 凭据或不必要的原始用户请求。网络失败、解析失败、拒绝校验、部分成功和缓存回退使用可区分状态。

每阶段至少验证：

1. A/HK 市场上下文、数据隔离、自选和代码规范化。
2. Provider 解析、来源/单位/时间元数据、响应限额、重试和最后有效缓存保留。
3. 领域契约与 UI 的 `available/limited/unavailable` 一致性。
4. 桌面与 Android 构建、响应式布局、离线读缓存和显式刷新路径。
5. 发布文档能力声明与代码/数据证据相符。

真实服务验收独立于自动测试，并在启用 provider 前确认服务可用性、使用条款、归属/署名要求及数据分发限制。一次在线请求不构成覆盖、完整性或回测有效性的证明。

## 非目标

- 不把港股功能作为 A 股的别名或通过更换代码前缀实现。
- 不默认接入衍生品、ETF 或其他与普通股有不同交易/估值语义的证券类别。
- 不用当前截面数据宣称历史点时准确性，不用实时缓存冒充披露历史。
- 不要求首个阶段同时上线所有能力；未开放能力必须有可理解状态和可追踪开放条件。
- 不借此改写 A 股策略的参数或既有结果语义。
